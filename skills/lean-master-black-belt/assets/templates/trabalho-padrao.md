# Template — Trabalho Padrão (Standard Work)

**Quando usar:** documentar a melhor forma atualmente conhecida de executar uma tarefa/etapa. **Lembrete de princípio:** isto é a baseline para o próximo experimento, não uma regra imutável (ver nuance 5 em `fundamentos-e-pilares.md`) — comunique isso ao usuário e, se for para uso com a equipe, ao time também.

## Cabeçalho
- Processo/etapa: ______
- Responsável pela execução: ______
- Data de criação / última revisão: ______
- Takt time da etapa: ______ (ver `glossario.md`)

## Sequência de trabalho padrão
| # | Passo | Tempo | Ponto-chave de qualidade/segurança | Por quê (razão do passo, não só o "o quê") |
|---|---|---|---|---|
| 1 | | | | |
| 2 | | | | |
| ... | | | | |

*A coluna "Por quê" não é opcional: sem entender a razão de um passo, o operador não consegue avaliar se uma mudança de contexto ainda respeita a intenção original do padrão.*

## Estoque padrão em processo (se aplicável)
Quantidade mínima de peças/itens necessária entre esta etapa e a próxima para o fluxo não parar.

## Layout / posicionamento
Diagrama simples (pode ser texto descritivo) de onde ficam ferramentas, materiais e o operador durante a execução.

## Como propor uma mudança ao padrão
1. Testar a mudança em pequena escala (PDCA — ver `pdca.md`).
2. Medir contra a métrica que o padrão atual busca proteger (tempo, qualidade, segurança).
3. Se supera o padrão atual de forma consistente, atualizar este documento com nova data de revisão e motivo da mudança registrado.
4. Se não supera, descartar sem atribuir culpa a quem propôs — a tentativa é o processo funcionando, não uma falha.

---

**Sinal de alerta:** se a adesão ao padrão está baixa, a primeira pergunta não é "como fazer cumprir", é "o que no padrão não funciona na prática, que o time descobriu e nós não vimos?" — investigar, não punir (mesmo princípio da nuance 5 em `fundamentos-e-pilares.md`).
