# Glossário de Especialista

Use para checar precisão de termo antes de usá-lo com o usuário. Definições curtas e técnicas — não simplifique a ponto de perder precisão.

| Termo | Definição |
|---|---|
| **Andon** | Sistema visual/sonoro de sinalização de problemas na linha. Qualquer operador pode parar o processo. Só funciona com equipe de resposta rápida (< 1 min) e cultura de não-punição — sem isso, Andon vira pânico, não controle. |
| **CONWIP** | Constant Work-In-Process. Sistema Pull onde um número fixo de "fichas" circula no sistema inteiro; quando uma tarefa termina, a ficha libera uma nova entrada. Diferente de Kanban (que limita WIP por estágio), CONWIP limita WIP global. |
| **Dock-to-Dock Time** | Tempo entre a matéria-prima chegar e o produto acabado sair. Métrica de fluxo — mais confiável que OEE isolado para saúde do sistema. |
| **Gemba** | "O lugar real". Ir ao Gemba é ir ao local onde o valor é criado (linha, atendimento, código sendo escrito) para observar, não para inspecionar. |
| **Heijunka** | Nivelamento da produção — misturar modelos/variedades ao longo do dia em vez de lotes homogêneos. Requer SMED para ser viável (mais variedade = mais setups). |
| **Jidoka** | Autonomação — "autonomia com julgamento humano". A máquina/operador para ao detectar anomalia. Diferente de automação pura. |
| **Muda** | Desperdício. Os 7 tipos: Transporte, Inventário, Movimento, Espera, Superprodução, Superprocessamento, Defeitos. |
| **Obeya** | "Grande sala" — sala de gestão visual para revisão diária de KPIs, problemas abertos e ações. Origem no desenvolvimento de produtos da Toyota (Prius). |
| **OEE** | Overall Equipment Effectiveness = Disponibilidade × Performance × Qualidade. Mede eficiência da máquina isolada, não do fluxo — cuidado ao usar como métrica única (ver "Paradoxo da Eficiência Local"). |
| **One-Piece Flow** | Processar uma unidade por vez entre estações, sem acumular inventário. Exige takt time balanceado entre postos; em processos de alta variabilidade (reparos, cirurgias), lotes pequenos podem ser mais realistas. |
| **PDCA** | Plan-Do-Check-Act. Plan: definir hipótese. Do: testar em pequena escala. Check: medir resultado. Act: padronizar se funcionou, ajustar se não. |
| **Poka-Yoke** | Mecanismo à prova de erro — torna o erro fisicamente impossível ou imediatamente óbvio, em vez de depender de atenção humana. |
| **Pull** | Produção puxada — processo posterior sinaliza necessidade ao anterior, via sistema explícito (Kanban, CONWIP, FIFO lane). |
| **SMED** | Single-Minute Exchange of Die — redução do tempo de setup para menos de 10 minutos. Técnica central: converter ajustes internos (máquina parada) em externos (máquina rodando). |
| **Takt Time** | Ritmo de produção necessário para atender a demanda do cliente = tempo disponível ÷ demanda do cliente. |
| **Trabalho Padrão** | Documento com a melhor forma atualmente conhecida de executar uma tarefa. Não é imutável — é a baseline para experimentação (ver nuance 5 em `fundamentos-e-pilares.md`). |
| **VSM** | Value Stream Mapping — mapeamento do fluxo de valor completo: tempo de processamento, tempo de espera, inventário entre etapas, fluxo de informação. A ferramenta de diagnóstico mais poderosa do Lean. |
